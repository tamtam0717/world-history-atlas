# データ作成担当への共通の指示（1648–1815 試作）

このリポジトリ（/home/user/world-history-atlas）は、年代別のヨーロッパ歴史地図。地図は「現代の行政区画（ピース）を、年ごとの所属に従って塗り分ける」方式で描く。あなたは担当地域のデータ（政体・地域と所属の変遷・出来事）を作る。

## 最初に読むもの
1. `CLAUDE.md`（プロジェクトの方針）
2. `docs/data-format.md`（データ形式と検証ツール。必読）
3. `docs/polity-ids.md`（政体 ID の割り当てと担当範囲。ほかの担当の政体はこの ID で参照する）
4. `data/events/europe.yaml`（ヨーロッパ全体の主な出来事。ここにあるものは重複して書かない）

## 作るもの
- 自分の担当ファイル（polities / regions / events）だけを作る・編集する。ほかの担当のファイル、`src/`、`tools/`、`docs/` は変更しない。
- **担当範囲のすべてのピースに、1648年から1815年までの所属を与える**（データなしのピースをゼロにする）。
  `node tools/build_data.mjs --missing 1648,1700,1750,1790,1800,1810,1815 --iso <担当の国コード>` で確認する。
- 国境の変化は、条約や併合の年で切り替える（年の決まりは data-format.md を参照）。主な変化をもれなく入れる。
- 自分が定義する主な政体には、1648–1815年の**君主を全員**（在位年つき）と、**情勢（periods）**を2〜6件入れる。小さな政体は君主を省略してよい。
- 担当地域の出来事を15〜40件程度入れる（europe.yaml と重複しないもの）。
- 名前は日本の高校世界史（山川出版社『詳説世界史』など）の表記に寄せる。
- 出典（source）はできるだけ付ける。記憶だけで書いて自信のないものは note に「要確認」と書く。

## 精度の考え方
- 主な使い方は「地図を眺めて全体像をつかむ」こと。ただし国境は**ピースの粒度でできる限り正確に**する。ピースが歴史的な境界をまたぐときは、面積の大きい側に入れる。
- 神聖ローマ帝国（`hre`）の枠：帝国に属する領域には `overlord: hre` を付ける（1806年まで）。ボヘミア王冠領（ボヘミア・モラヴィア・シュレジエン・ラウジッツ）、オーストリア諸邦、南ネーデルラント（ブルグント・クライス）、ホルシュタイン、スウェーデン領ポンメルンなどは帝国内。ハンガリー・クロアチア、プロイセン公国（東プロイセン）、シュレースヴィヒ、スイス、オランダは帝国外。帝国イタリア（ミラノ、トスカーナなど北・中部イタリアの諸国）は、このプロジェクトでは**帝国の枠に含めない**（トレンティーノ・南チロル・ゴリツィア・トリエステなどオーストリア・クライスに属した地域は含める）。
- ナポレオン期（1806–1813）のライン同盟加盟国は `overlord: rhine_confederation`、1815年のドイツ連邦は `overlord: german_confederation`。
- 戦時の一時占領は描かない（正式な割譲で切り替える）。ナポレオン期のように長く続いた占領で、地図の理解に必要なものだけ `certainty: occupied` を使ってよい。

## 検証（必ず行う）
1. `npm run data` で警告を確認する。自分のファイルに関する警告はなくす（ほかの担当の政体がまだ未定義、という警告は無視してよい）。
2. `~/venv/bin/python tools/compare_hb.py <年> --iso <担当の国コード>` を 1650, 1700, 1715, 1783, 1800, 1815 で実行し、食い違いを一つずつ調べる。
   - historical-basemaps（照合先）は粗く、間違いも多い。自分が正しいと判断したら直さなくてよいが、最終報告に理由を書く。
   - **照合先のデータを自分のデータに写してはいけない（ライセンスが GPL のため）。** 照合にだけ使う。
   - `~/venv/bin/python` がないときは `/home/user/venv/bin/python` を使う。
3. `node tools/snapshot.mjs 1648 1700 1750 1789 1800 1812 1815 --zoom <経度>,<緯度>,<倍率> --out .cache/snapshots/<担当名>` で地図を書き出し、画像を見て確認する（Read ツールで PNG を開ける）。ピースの境界を見たいときは `--debug` を付ける。

## してはいけないこと
- git の commit / push（まとめ役が行う）。
- 担当範囲外のピースを select に入れること（重なりの決まりで、ほかの担当のデータを上書きしてしまうため）。
- ほかの担当のファイルの編集。

## 最後に報告すること（日本語で、簡潔に）
- 作った政体・地域・出来事の数、データなしピースの残り（0 が目標）
- 判断に迷った点、通説が分かれる点、自信のない点（ファイル名と ID つき）
- historical-basemaps との食い違いで、直さなかったものとその理由
- ほかの担当との境界で、整合を確認してほしい点（例：「ポメラニアの1720年の境界を BN と F で合わせる必要あり」）
